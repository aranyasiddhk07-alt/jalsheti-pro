### 2.1 `users` — Primary user table (linked to auth.users via trigger)

```sql
CREATE TABLE public.users (
  id UUID PRIMARY KEY,                           -- MUST EQUAL auth.users.id (enforced by trigger)
  phone VARCHAR(15) UNIQUE NOT NULL,
  name VARCHAR(100) NOT NULL DEFAULT '',
  role VARCHAR(20) NOT NULL CHECK (role IN ('superadmin','supplier','consumer')),
  village VARCHAR(100),
  taluka VARCHAR(100),
  district VARCHAR(100) DEFAULT 'Kolhapur',
  referral_code VARCHAR(20) UNIQUE,
  referred_by UUID REFERENCES public.users(id),
  linked_supplier_id UUID REFERENCES public.users(id),
  is_active BOOLEAN DEFAULT true,
  subscription_status VARCHAR(20) DEFAULT 'trial'
    CHECK (subscription_status IN ('trial','active','expired','free','cancelled')),
  trial_ends_at TIMESTAMPTZ,
  consent_granted_at TIMESTAMPTZ,
  acquisition_source VARCHAR(50),
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

**RLS Policies:**
- `CREATE POLICY "Users see own profile" ON users FOR SELECT USING (auth.uid() = id);`
- `CREATE POLICY "Users update own profile" ON users FOR UPDATE USING (auth.uid() = id);`
- `CREATE POLICY "Supplier sees linked consumers" ON users FOR SELECT USING (linked_supplier_id = auth.uid() AND role = 'consumer');`

**Notes:**
- `id` is SET by the auth trigger, NOT generated by gen_random_uuid()
- `subscription_status = 'free'` for suppliers (they never pay)
- `subscription_status = 'trial'` for new consumers (7-day free period)

```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.users (id, phone, name, role)
  VALUES (NEW.id, NEW.phone, '', 'consumer');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();

## 5. RLS POLICIES (004_rls_policies.sql) — 31 policies

**CRITICAL RULE: Money tables (commission_wallet, subscriptions, savings_log) have NO client INSERT/UPDATE/DELETE. This is intentional, not accidental. Writes happen ONLY via Edge Functions with service_role key.**

```
users:               SELECT own, UPDATE own, Supplier SELECT linked consumers
fields:              Consumer ALL, Supplier SELECT
soil_cards:          Consumer ALL
water_schedules:     Supplier ALL, Consumer SELECT
water_sessions:      Consumer ALL, Supplier SELECT + acknowledge UPDATE
crop_advisories:     Consumer SELECT
notifications:       User ALL + system INSERT
pest_alerts:         Consumer SELECT + acknowledge UPDATE
savings_log:         Consumer SELECT (NO CLIENT WRITES)
commission_wallet:   Supplier SELECT (NO CLIENT WRITES)
supplier_referrals:  Both parties SELECT
subscriptions:       Consumer SELECT (NO CLIENT WRITES)
market_rates:        Authenticated SELECT, Admin ALL
insurance_claims:    Consumer ALL
weed_identifications:Consumer ALL
organic_resources:   Consumer ALL
liquid_organic_log:  Consumer ALL
supplier_assignment_history: Consumer own + involved supplier SELECT
audit_log:           Admin SELECT ONLY
engine_feedback:     Consumer ALL
job_queue:           NO CLIENT ACCESS
feature_flags:       Authenticated SELECT

STORAGE BUCKETS:
  insurance-photos:  10MB limit, JPEG/PNG/WebP, owner-only upload/view
  crop-diagnosis:    10MB limit, JPEG/PNG/WebP, owner-only upload/view

## 6. DATA RETENTION POLICY

- `notifications`: Auto-delete rows older than 90 days (cron job)
- `water_sessions`: Partition by month, archive partitions older than 2 years to cold storage
- `audit_log`: Retain indefinitely (immutable)
- `savings_log`, `commission_wallet`, `subscriptions`: Retain indefinitely (append-only financial records)
- User data: Soft-delete on account closure (is_active = false), hard delete after 30-day grace period per DPDP Act
